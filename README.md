# TimeCounter

Персональный счётчик активности Windows/RDP. Один автономный `TimeCounter.exe`, Windows 10 LTSC 2021 (21H2, как на скриншоте) / Windows 11, x64. Устанавливать .NET, библиотеки или службу не нужно. Сборка включает среду .NET 10; при первом запуске системные библиотеки извлекаются в пользовательский временный каталог.

## Запуск

Скачайте EXE из [Releases](https://github.com/evilguest/TimeCounter/releases), поместите в постоянный каталог и запустите **внутри той RDP-сессии, активность которой нужно учитывать**. На локальном компьютере приложение отслеживает локальную сессию. Нужны обычные пользовательские права. Один экземпляр на пользователя, в том числе между его сессиями.

В трее доступны выход, скрытие/показ цифр, настройки и история. Оверлей не получает фокус и пропускает мышь. По умолчанию: верхний правый угол рабочего пространства первого монитора, Agency FB 144 pt, красный, прозрачность 75% (видимость 25%). Если шрифта нет в Windows, используется системная замена; шрифты не поставляются с приложением. Размер и отступы ограничиваются границами экрана. Поверх обычных окон; защищённый рабочий стол Windows и эксклюзивный полноэкранный режим не поддерживаются.

Настройки: таймаут, шрифт, размер, цвет, прозрачность, монитор, угол и отступы, автозагрузка текущего пользователя, порт API. Автозагрузка хранит путь к EXE; после перемещения файла переключите её заново. При входе в Windows приложение запускается свёрнутым в трей.

## Правила подсчёта

- Сессия подключена и разблокирована: активное время до истечения таймаута после последнего ввода клавиатуры/мыши (по умолчанию 5 минут). Сам период ожидания таймаута остаётся активным, без ретроспективного вычитания.
- Блокировка Win-L, отключение RDP и простой после таймаута: неактивное время. Используются Windows WTS notifications и GetLastInputInfo текущей сессии; состояние дополнительно опрашивается каждую секунду.
- Сон/гибернация и задержка опроса более 10 секунд: весь пропущенный интервал консервативно считается неактивным, поскольку ввод подтвердить нельзя.
- Приложение выключено: непосчитанное время. До первого запуска в этот день — тоже непосчитанное. При аварийном завершении может потеряться до 15 секунд последних наблюдений.
- Сегодня: от местной полуночи до текущего момента; будущая часть дня не включается. Прошлые дни: целые местные сутки, включая переходы летнего времени. В оверлее, подсказке трея и истории отображаются часы:минуты без секунд (неполная минута отбрасывается). API возвращает секунды с дробной частью.
- Интервалы хранятся в UTC, группируются по текущей локальной таймзоне Windows. Смена таймзоны меняет группировку старых интервалов; перезапустите приложение после смены таймзоны. При переводе часов назад повторно один интервал не засчитывается. Для нормального учёта нужны корректные системные часы.

Это независимое измерение. Совпадение с официальной системой зависит от её таймаута, правил округления, учёта сна и периода до достижения таймаута. Приложение не эмулирует ввод и не влияет на официальный счётчик.

## Данные

- Настройки и токен: `HKCU\Software\TimeCounter`, значение `Settings` (JSON).
- Автозагрузка: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\TimeCounter`.
- История: `%LOCALAPPDATA%\TimeCounter\history.json`; атомарная запись каждые 15 секунд и при штатном выходе, предыдущая версия `.bak`.
- Ошибки: `%LOCALAPPDATA%\TimeCounter\errors.log`.

При повреждении истории приложение сообщает об ошибке и сохраняет исходный файл. Для восстановления закройте приложение, скопируйте повреждённый файл в другое место, восстановите `history.json.bak` как `history.json`. Данные ввода и названия окон не сохраняются, только интервалы и признак активности. История не удаляется автоматически.

## HTTP API

Слушает IPv4 и IPv6 на всех интерфейсах, по умолчанию TCP **47831**. Администратор и URL ACL не нужны. Если порт занят, учёт продолжится, появится уведомление; выберите другой порт в настройках. Токен генерируется при первом запуске, виден в настройках, необходим в каждом запросе. Только чтение:

```bash
export TIMECOUNTER_URL='http://WINDOWS_HOST:47831'
# Задайте TIMECOUNTER_TOKEN значением из настроек.
curl --fail-with-body --connect-timeout 5 --max-time 20 \
  -H "Authorization: Bearer ${TIMECOUNTER_TOKEN}" \
  "${TIMECOUNTER_URL}/api/history?days=7"
```

`days=0` или отсутствие параметра — сегодня. `days=7` — сегодня плюс семь предыдущих дат (8 строк), диапазон 0–3660. Отсутствующие старые данные отображаются как непосчитанное время. Ответ:

```json
{
  "generatedAt": "2026-11-12T12:00:00+00:00",
  "timeZone": "N. Central Asia Standard Time",
  "days": [{
    "date": "2026-11-12",
    "activeSeconds": 18000,
    "inactiveSeconds": 3600,
    "uncountedSeconds": 46800,
    "elapsedSeconds": 68400
  }]
}
```

Снимок отстаёт от текущего момента примерно на секунду. Коды: 200, 400 (параметры), 401 (токен), 404 (путь), 405 (метод), 431 (слишком большой заголовок). Ограничение заголовков 8 KiB, таймаут подключения клиента 5 секунд, не более 16 обслуживаемых клиентов одновременно.

HTTP не шифруется. Используйте доверенную сеть/VPN/SSH; токен не заменяет шифрование. Приложение само не меняет Windows Firewall. При необходимости разрешите входящий TCP-порт только для IP Linux-машины и нужного профиля сети, в рамках правил вашей организации. Не открывайте его в интернет.

## Skill для Codex на Linux

Скопируйте папку [`skills/timecounter-api`](skills/timecounter-api) в `~/.codex/skills/timecounter-api` на Linux. Передайте Codex адрес машины и токен, либо задайте `TIMECOUNTER_URL` и `TIMECOUNTER_TOKEN` в его окружении. Например: «Используй $timecounter-api, покажи активное время за последние семь дней включая сегодня». Skill ничего не меняет через API.

## Сборка и проверка

Нужен .NET SDK 10 на Windows. Внешних NuGet-пакетов нет; SDK может скачать официальные runtime packs Microsoft при первой публикации.

```powershell
dotnet build TimeCounter/TimeCounter.csproj -c Release
dotnet run --project TimeCounter.Tests -c Release
dotnet publish TimeCounter/TimeCounter.csproj -c Release -o dist
```

Результат: `dist/TimeCounter.exe`. PDB для запуска не нужен. Проверки без тестовых пакетов охватывают таймаут, отключение, полночь, DST, полноту суток, сохранение и резервную копию, перевод часов назад, HTTP авторизацию/маршруты/диапазоны, стили оверлея и открытие окон. UI-проверки требуют интерактивного рабочего стола Windows: они временно перемещают курсор и нажимают каждый пункт меню трея, в том числе повторное скрытие/показ, затем возвращают курсор на место.

Ручная проверка на целевой машине: запустить в RDP, выставить таймаут 1 минуту, проверить начало простоя, Win-L и отключение/подключение RDP; проверить сон/возобновление, клик через цифры, автозагрузку и запрос с Linux. Реальное отключение RDP, Windows 10 LTSC и доступ через межсетевой экран нельзя подтвердить модульным тестом на машине разработки.

Совместимость среды: [поддерживаемые версии Windows для .NET](https://learn.microsoft.com/en-us/dotnet/core/install/windows). Техническая основа: [WTS notifications](https://learn.microsoft.com/en-us/windows/win32/termserv/wm-wtssession-change), [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo).
